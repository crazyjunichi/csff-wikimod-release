WikiMod 脚本系统使用指南

1. 快速入门

打开万能修改器，找到「脚本工具」页面。你会看到左边是脚本列表，右边是编辑区。

试试写下你的第一个脚本：

河流.饮用

点击「运行」，脚本会自动帮你对「河流」执行「饮用」动作。就这么简单。

2. 基础概念

什么是脚本

脚本是一段文本，告诉游戏"自动帮我做哪些操作"。你可以用它来：

  • 重复执行某个动作（比如反复砍柴）
  • 按顺序执行多个操作（比如先加水，再加料，再煮）
  • 根据条件决定做什么（比如"有肉干就吃掉，没有就算了"）

脚本文件

脚本保存在 BepInEx/config/WikiMod/Scripts/ 目录下，扩展名为 .wks。你也可以用任何文本编辑器直接编辑这些文件。

脚本名称就是文件名（不含扩展名），显示在左侧列表中。

界面操作

  • 新建 — 创建一个空白脚本
  • 保存 — 保存当前编辑内容到文件
  • 检查 — 检查脚本是否有语法错误
  • 运行 — 执行脚本
  • 停止 — 中止正在运行的脚本
  • 打开文件夹 — 在资源管理器中打开脚本目录

另外，点击界面上的"快捷键: 无"按钮可以为当前脚本绑定一个独立快捷键。

快捷键

每个脚本都可以通过 @hotkey 指令或界面上的快捷键按钮绑定独立快捷键，按下即执行该脚本，再按一次停止。

3. 脚本语法

3.1 注释和元数据

# 这是注释，不会被执行
# 可以用来写备注

@error stop
@hotkey F5
@silent

注释：以 # 开头的行会被忽略，随便写什么都行。

@error：决定遇到错误时怎么办：

  • @error stop — 出错就停（默认）
  • @error continue — 出错了跳过，继续执行后面的

@hotkey：为脚本绑定快捷键，值为 Unity 的 KeyCode 名称（如 F5、Tab、Alpha1 等）。绑定后按对应键即可执行该脚本。

@silent：加上这一行，脚本执行完毕后不会弹出结果对话框。适合频繁执行的短脚本。

3.2 卡牌操作

这是脚本最核心的功能——自动执行卡牌动作。

单一卡牌动作（对卡牌执行动作）

河流.饮用
River.Drink

格式：卡牌名.动作名

意思是"找到这张卡牌，然后执行这个动作"。就像你在游戏里右键点击卡牌，然后选择某个动作一样。

卡牌交互（把一张卡拖到另一张上）

石斧+橡树
Axe_Stone+TreeOakLarge

格式：给予卡牌+接收卡牌

意思是"把左边的卡牌放到右边的卡牌上"。就像你在游戏里拖拽操作一样。

独立动作（不指定卡牌）

休息
北方
do Rest

格式：直接写动作名，或 do 动作名

直接写动作名时，系统会依次在以下位置查找匹配的动作：

  1. 时间选项（TimeOptions）中的动作（如"休息"、"睡觉"等）
  2. 当前场景中卡牌的动作（如当前地点卡的"北方"、"南方"等移动动作）

这是一种语法糖——如果动作名在当前环境中是唯一的，无需指定卡牌名即可执行。

等待

wait 2

让脚本暂停指定秒数（支持小数）。有些操作需要等待动画播完，或者等资源刷新。

wait_frame 5

按帧等待，暂停指定帧数。适合精确控制等待时长。

wait_until exists(河流) timeout 10

等待条件成立后继续执行。可选 timeout 参数指定超时秒数（默认 60 秒），超时后自动继续。

3.3 卡牌选择器

当你场景里有多张同名卡牌时，选择器帮你指定要操作哪一张。

默认选择（第一张）

河流.饮用

不加任何选择器，就操作找到的第一张。

按编号选择

河流[0].饮用      # 第1张
河流[1].饮用      # 第2张
河流[2].饮用      # 第3张

编号从 0 开始。[0] 就是第一张，[1] 是第二张，以此类推。

按属性选择

肉干[max:变质].吃掉     # 选变质最高的那张先吃
肉干[min:变质].吃掉     # 选变质最低的那张先吃
  • [max:属性名] — 选指定属性值最大的那张
  • [min:属性名] — 选指定属性值最小的那张

属性名可以是游戏中显示的中文名（如"变质"、"燃料"、"耐久"），也可以是内部英文名称。

条件过滤

肉干[变质>80].吃掉              # 只选变质大于80的肉干
储物箱[inventory>0].清空        # 只选有内部物品的储物箱
肉干[变质>50, max:变质].吃掉    # 变质>50的肉干中，选变质最高的
木头[耐久>=10, 0]               # 耐久>=10的木头中，取第一张

在方括号内写 属性名 运算符 数值 作为过滤条件，只有满足条件的卡牌才参与后续选择。

  • 支持运算符：>、<、>=、<=、=
  • 可用逗号组合多个过滤条件和一个选择策略（max:/min:/索引）
  • 特殊属性名 inventory：代表卡牌内部物品总数量（排除空槽位）

指定位置

肉干[in:保险罐].吃掉                    # 只选在保险罐里的肉干
肉干[in:保险罐, max:变质].吃掉          # 保险罐中变质最高的肉干
木柴[in:场景]                            # 只选场景（户外）的木柴
石斧[in:手中]                            # 只选在手中的石斧
铁甲[in:装备]                            # 只选装备中的铁甲
木板[in:场上]                            # 只选在场上/室内的木板

[in:位置] 限定卡牌必须在指定位置。可与条件过滤、选择策略组合使用。

支持的特殊位置关键字：

关键字 含义
手中 / hand 玩家手中的卡牌
装备 / equipped 装备中的卡牌
场景 / location 场景中的卡牌（户外环境）
场上 / base 场上的卡牌（基地/室内）

其他值按容器名匹配（如 in:保险罐、in:背包）。

包含内容

保险罐[has:肉干]                     # 装有肉干的保险罐
水壶[has:水]                         # 装有水的水壶（检查物品和液体）
容器[has:肉干, inventory>3]          # 装有肉干且内部物品>3的容器

[has:名称] 筛选包含指定物品或液体的卡牌。同时检查内部物品（CardsInInventory）和内部液体（ContainedLiquid）。可与其他过滤条件组合使用。

特殊名称用引号

如果卡牌名或动作名里含有 + [ ] 空格等符号，用双引号包起来：

"带空格的卡牌"[0].动作

3.4 生成与检查

生成蓝图：blueprint

blueprint 木屑
blueprint 木屑 3

格式：blueprint 蓝图卡名 [数量]

在当前环境中生成一张蓝图卡实例。数量可省略，默认为 1。仅生成空白蓝图，不进行填充与建造。

⚠ blueprint 仅支持蓝图卡。传入普通物品会报错"blueprint 仅支持蓝图卡，<X> 不是蓝图卡"——这是为了避免脚本被用来凭空生成普通物品作弊。

旧版本的 spawn 命令已禁用，遇到会报错"spawn 命令已禁用"；普通物品请通过对应蓝图建造产出。

一键建造蓝图：build ⭐

build 木屑
build Bp_Cabin

要批量建造，把 build 放在 repeat 块里：

repeat 5 {
    build 木板房
}

格式：build 蓝图卡名

最常用的蓝图建造写法：一行命令完成"创建蓝图（若不存在）→ 打开面板 → 等待 2 帧 → 自动填充 → 点击制作"整套流程。每次调用只建造一份。

执行特性：

  • 复用而不重复：当前环境里已有同款未完工蓝图就直接拿来填充，不会再凭空 spawn 一张同样的蓝图堆叠。
  • 遇错即停：未解锁、缺材料、缺耐久、属性不足、状态阻塞等任何一步失败，整段终止并在日志里给出具体原因（如"自动填充后仍无法制作: 缺卡牌: 石头; 属性不满足: 体力"）。
  • 仅查"已解锁蓝图"：build 的目标只在已解锁的蓝图列表里按名字匹配。所以 build 营火 即使环境里同时有普通"营火"卡，也会准确命中 Bp_Campfire，不会被同名普通物品截胡。蓝图未解锁时会报错"未找到已解锁的蓝图: <名称>"。
  • 不接受标签：传卡牌标签（如 build 食物）会在校验阶段就被拒绝。
  • 优先用内部 ID：写成 build Bp_Cabin 最稳妥，可避免本地化文本变更或两个蓝图同名等罕见情况。

打开面板：inspect

inspect 河流
inspect 木板[0]

格式：inspect 卡牌选择器

打开指定卡牌的检查面板。通常配合 click 使用。

点击按钮：click

inspect 河流
click 饮用

格式：click 按钮名

点击当前已打开面板上的按钮。需要先用 inspect 打开卡牌面板，然后才能 click。按钮名就是面板上显示的文字。

支持的按钮类型：选项按钮、分组选项按钮、清空背包按钮、建造/拆除按钮、自动填充按钮等。

3.5 消息命令

提示消息：toast

toast 你好，世界
toast "采集完成，共获得5块木板"

格式：toast 消息内容

在屏幕上显示一条浮动提示，会自动消失。不会阻断脚本执行。

弹窗消息：alert

alert 请确认后继续
alert "操作已完成"

格式：alert 消息内容

弹出一个居中对话框，用户点击「关闭」或按 ESC 后脚本才继续执行。适合需要暂停等待用户确认的场景。

集中液体：liquid_merge

liquid_merge 水壶
liquid_merge 水壶[in:手中]
liquid_merge 容器[has:水]

格式：liquid_merge 选择器

将匹配到的液体容器中的同类液体集中到尽量少的容器中（优先填满）。不同种类的液体会自动分组，各自集中，不会混合。

使用游戏原生的液体转移机制，因此会遵守容器的最低保留量等游戏规则。匹配到的含液体容器少于 2 个时不执行。

模板表达式

toast 和 alert 的消息内容支持用 {表达式} 嵌入游戏数据，运行时自动替换为实际值：

toast 石斧耐久：{石斧.耐久}
toast 肉干数量：{count(肉干)}
alert "当前饥饿值：{饥饿}"

支持的表达式：

  • {卡牌名.属性名} — 卡牌属性值（如 {石斧.耐久}）
  • {卡牌名[选择器].属性名} — 带选择器的属性值（如 {石斧[0].耐久}）
  • {count(卡牌名)} — 卡牌数量（如 {count(肉干)}）
  • {exists(卡牌名)} — 卡牌是否存在，显示"是"或"否"
  • {inventory_count(卡牌名)} — 卡牌内部物品总数量（如 {inventory_count(背包)}）
  • {状态名} — 游戏状态值（如 {饥饿}、{HP}）

表达式求值失败时，原始 {表达式} 文本会原样保留，不影响消息显示。

3.6 控制流

循环：repeat

repeat 10 {
    河流.饮用
}

重复执行大括号里的内容 N 次。上面的例子会连续对河流执行 10 次饮用。

可以嵌套：

repeat 3 {
    石斧+橡树
    repeat 2 {
        河流.饮用
    }
}

条件：if / else if / else

if exists(河流) {
    河流.饮用
}

只有条件成立时，才执行大括号里的内容。

可以用 else if 和 else 添加分支：

if exists(河流) {
    河流.饮用
} else if exists(水壶) {
    水壶.饮用
} else {
    toast 没有水源
}

注意：{ 必须和 if / else if / else 写在同一行。else 可以紧跟在前一个 } 的下一行，也可以与 } 写在同一行（K&R 风格 } else { / } else if (...) {）。

条件循环：while

while 营火.燃料 < 30 and exists(木柴) {
    木柴+营火
}

只要条件成立就重复执行。每轮循环后会自动让出一帧避免阻塞。为防止死循环，最大迭代次数为 10000 次。

循环控制：break / continue / stop

repeat 10 {
    if not exists(肉干) {
        break
    }
    肉干.吃掉
}
  • break — 跳出当前循环
  • continue — 跳过本轮，进入下一轮循环
  • stop（或 exit）— 立即终止整个脚本

break 和 continue 只能在循环（repeat / while / foreach）内使用。

变量：var

var target = 肉干[max:变质]
$target.吃掉

var count = 5
var backup = $target

用 var 定义变量：

  • 数字值：var x = 42
  • 卡牌引用：var t = 肉干[max:变质]（在定义时查找卡牌）
  • 属性值：var v = 肉干[max:变质].变质（获取卡牌属性的数值）
  • 复制变量：var b = $t（复制另一个变量的值）

在卡牌操作和条件中使用 $变量名 引用卡牌变量：

var t = 肉干[max:变质]
$t.吃掉
if $t.变质 > 80 {
    toast 快坏了！
}

在模板表达式中用 {$变量名} 引用：

var t = 肉干[max:变质]
toast 变质度：{$t.变质}
log 当前目标：{$t}

遍历：foreach

foreach item in 肉干 {
    if $item.变质 > 80 {
        $item.吃掉
    }
}

遍历场景中所有匹配的同名卡牌。每轮循环中，变量名会绑定到当前卡牌。在条件和卡牌操作中使用 $变量名 引用。支持 break / continue。

调用子脚本：call

call 子脚本名

调用另一个脚本（按脚本名查找）。子脚本有独立的变量空间，不与父脚本共享变量。子脚本的日志会合并到父脚本。如果子脚本执行出错，错误会传播给父脚本。

日志：log

log 当前燃料：{营火.燃料}
log 变量值：{$target.变质}

写入日志但不弹窗。支持模板表达式。日志可在执行结果中查看。

3.7 条件表达式

exists — 卡牌是否存在

if exists(河流) {
    河流.饮用
}

检查当前场景中是否有这张卡牌。

count — 卡牌数量

if count(肉干) >= 3 {
    肉干.吃掉
}

检查当前场景中某卡牌有几张，可以用 >、<、>=、<=、==、!= 进行比较。

属性比较

if 营火.燃料 > 10 {
    # 燃料还够，不用加柴
}

if 肉干.变质 > 80 {
    # 快坏了，赶紧吃
    肉干[min:变质].吃掉
}

检查卡牌的某个属性值。格式：卡牌名.属性名 运算符 数值

状态比较

if HP > 50 {
    # 生命值足够
}

检查游戏全局状态值。格式：状态名 运算符 数值

变量比较

var c = 树叶[min:湿度].湿度
if $c > 100 {
    toast 湿度很高：{$c}
}

检查变量值。格式：$变量名 运算符 数值。变量必须是数值类型（通过 var x = 卡牌.属性 获得）。

也可以在条件中直接访问变量卡牌的属性：

var t = 肉干[max:变质]
if $t.变质 > 80 {
    $t.吃掉
}

逻辑运算符

条件可以用逻辑运算符组合：

if exists(河流) and count(肉干) >= 3 {
    河流.饮用
}

if not exists(营火) or 营火.燃料 < 5 {
    # 没有营火或燃料不足
}

if (exists(河流) and exists(石斧)) or count(肉干) > 10 {
    石斧+橡树
}
  • and 或 && — 逻辑与，两边都为真才为真
  • or 或 || — 逻辑或，任一为真即为真
  • not 或 ! — 逻辑非，取反
  • 支持用 () 括号控制优先级

3.8 完整指令形式

上面的语法糖（卡牌.动作 和 卡牌+卡牌）实际上是简写。完整形式如下：

# 单一卡牌动作的完整写法
do River.Drink
do 肉干[min:变质].吃掉

# 卡牌交互的完整写法
interact 石斧 橡树
interact Axe_Stone TreeOakLarge

两种写法效果完全一样，用哪种都行。

4. 名称规则

卡牌名怎么写

脚本会按以下顺序尝试匹配卡牌名：

  1. 游戏中显示的名称（当前语言）
  2. 英文原名
  3. 内部资源ID（如 Bp_WoodShavings）

建议：直接写游戏里显示的中文名就行，比如"河流"、"石斧"、"橡树"。

支持卡牌标签（CardTag）

除了直接写卡牌名，你还可以写卡牌标签名。系统会优先按卡牌名匹配，如果找不到对应的卡牌，就会自动尝试按标签查找。

斧头+大树

上面的"斧头"和"大树"都是标签名（CardTag），系统会从当前环境中找到带对应标签的卡牌来执行交互。

标签名支持以下写法：

  1. 标签的显示名称（当前语言，如"斧头"、"大树"）
  2. 标签的英文原名
  3. 标签的内部资源ID（如 tag_HumanFood）

标签可以用在所有需要卡牌名的地方，包括：

  • 卡牌动作：标签名.动作
  • 卡牌交互：斧头+大树
  • 条件判断：exists(标签名)、count(标签名)
  • 选择器：标签名[max:属性]、标签名[min:属性]

动作名怎么写

同样写游戏里显示的名称即可。比如对着河流右键看到"饮用"，就写 河流.饮用。

属性名怎么写

属性可以用游戏中显示的中文名（如"耐久"、"燃料"），也可以用内部英文名称。具体哪个属性对应什么含义，取决于具体卡牌。

环境限制

脚本只能操作当前所在环境的卡牌。如果你在室外，就操作不了房子里面的东西；如果你在帐篷里，就操作不了外面的卡牌。

5. 错误处理

检查功能

点击「检查」按钮可以在运行前发现问题：

  • 语法错误：拼写错误、缺少括号等
  • 语义错误：卡牌名不存在、动作名写错了

错误会显示在编辑器下方，标明行号和原因。

两种错误模式

@error stop       # 遇到任何错误就停止整个脚本（默认）
@error continue   # 遇到错误跳过那一步，继续执行后面的

什么时候用 continue？

当你要批量处理，有些卡牌可能已经不在了：

@error continue

repeat 20 {
    肉干.吃掉
}

这样即使场上只有 3 块肉干，吃完就会跳过错误继续（而不是报错停止）。

常见错误

  • 找不到卡牌: xxx — 卡牌名写错了，检查游戏中的实际名称
  • 找不到动作: xxx — 动作名写错了，右键卡牌看看实际的动作名
  • 期望 '{' — 循环或条件缺少大括号，写成 repeat 5 { 或 if ... {
  • 缺少 '}' — 大括号没关上，在块的末尾加 }

6. 实战示例

示例1：重复取水

@error continue

repeat 10 {
    河流.饮用
}

连续从河流取水 10 次。@error continue 保证即使河流不在也不会中途报错停止。

示例2：条件判断自动加柴

@error continue

repeat 20 {
    if exists(营火) {
        if exists(木柴) {
            木柴+营火
        }
    }
}

检查营火和木柴是否都存在，如果都有就自动加柴。重复 20 次。

示例3：智能选择器

@error stop

if exists(肉干) {
    肉干[max:变质].吃掉
}

选择变质最高（即最快要坏的）的肉干先吃，避免浪费。

示例4：砍树取材

@error continue

repeat 5 {
    石斧+橡树
}

用石斧对橡树进行 5 次交互，批量砍伐取材。

示例5：一键建造蓝图

@silent

build 木屑

build 一行搞定整套流程：（如环境无未完工蓝图就）创建蓝图 → 打开面板 → 自动填充 → 点击制作。@silent 让执行完后不弹提示。仅支持已解锁的蓝图卡，材料不足时会在日志里报具体原因。

批量制作时配合 repeat：

repeat 5 {
    build 木屑
}

示例6：消息提示与确认

@error continue

repeat 5 {
    石斧+橡树
}
toast 砍伐完成，石斧耐久：{石斧.耐久}
alert "是否继续？"

砍完树后用 toast 提示石斧耐久，再用 alert 弹窗等待确认。

示例7：逻辑组合条件

@error continue
@hotkey F5

repeat 10 {
    if exists(木柴) and 营火.燃料 < 30 {
        木柴+营火
    }
}

只在有木柴且营火燃料不足 30 时才加柴。绑定到 F5 快捷键方便随时执行。

7. 参考速查表

语法一览

  • 卡牌.动作 — 单一卡牌动作（如 河流.饮用）
  • 卡牌A+卡牌B — 卡牌交互（如 石斧+橡树）
  • 动作名 — 独立动作，无需卡牌（如 休息、北方）
  • wait N — 等待 N 秒（如 wait 2、wait 0.5）
  • wait_frame N — 等待 N 帧（如 wait_frame 5）
  • wait_until 条件 [timeout N] — 等待条件成立（如 wait_until exists(河流) timeout 10）
  • repeat N { } — 循环 N 次
  • while 条件 { } — 条件循环
  • foreach 变量 in 卡牌名 { } — 遍历卡牌
  • if 条件 { } — 条件执行
  • if ... { } else if ... { } else { } — 多分支条件
  • var 名 = 值 — 定义变量
  • break — 跳出循环
  • continue — 跳过本轮
  • stop / exit — 终止脚本
  • call 脚本名 — 调用子脚本
  • log 消息 — 写入日志
  • blueprint 蓝图卡名 [数量] — 生成蓝图卡（仅支持蓝图卡，如 blueprint 木屑）
  • build 蓝图卡名 — 一键建造蓝图（spawn→inspect→自动填充→制作 一条龙；如 build Bp_Cabin）
  • inspect 选择器 — 打开检查面板（如 inspect 河流）
  • click 按钮名 — 点击面板按钮（如 click 饮用）
  • toast 消息 — 显示浮动提示（如 toast 采集完成）
  • alert 消息 — 弹窗等待确认（如 alert 请确认）
  • liquid_merge 选择器 — 集中液体（如 liquid_merge 水壶[in:手中]）
  • @error stop/continue — 错误策略
  • @hotkey 键名 — 绑定快捷键（如 @hotkey F5）
  • @silent — 静默执行
  • # 文字 — 注释

选择器

  • 卡牌名 — 第一张匹配的
  • 卡牌名[0] — 第 1 张
  • 卡牌名[1] — 第 2 张
  • 卡牌名[max:属性] — 属性最高的那张
  • 卡牌名[min:属性] — 属性最低的那张
  • 卡牌名[属性>值] — 满足条件的第一张（支持 > < >= <= =）
  • 卡牌名[inventory>N] — 内部物品数量大于 N 的第一张
  • 卡牌名[in:位置] — 只选在指定位置的卡牌（手中/装备/场景/场上/容器名）
  • 卡牌名[has:物品名] — 只选包含指定物品或液体的卡牌
  • 卡牌名[条件, max:属性] — 先过滤再排序（逗号组合）
  • "特殊名称" — 含特殊字符的名称

条件

  • exists(卡牌名) — 场景中是否有这张卡（也支持标签名）
  • count(卡牌名) > N — 这张卡的数量是否大于 N（也支持标签名）
  • 卡牌.属性 > N — 卡牌的属性是否大于 N
  • $变量名.属性 > N — 变量卡牌的属性是否大于 N
  • 状态名 > N — 游戏状态是否大于 N
  • $变量名 > N — 数值变量是否大于 N
  • 条件1 and 条件2 — 逻辑与
  • 条件1 or 条件2 — 逻辑或
  • not 条件 — 逻辑非
  • (条件) — 括号分组

模板表达式（用于 toast / alert / log）

  • {卡牌.属性} — 属性值（如 {石斧.耐久}）
  • {卡牌[选择器].属性} — 带选择器（如 {石斧[0].耐久}）
  • {count(卡牌名)} — 数量（如 {count(木板)}）
  • {exists(卡牌名)} — 是否存在（显示"是"/"否"）
  • {inventory_count(卡牌名)} — 内部物品总数量（如 {inventory_count(背包)}）
  • {状态名} — 状态值（如 {饥饿}）
  • {$变量名} — 变量值（如 {$target}）
  • {$变量名.属性} — 变量卡牌的属性（如 {$target.变质}）

比较运算符

>、<、>=、<=、==（等于）、!=（不等于）

快捷键

  • @hotkey 绑定 — 执行/停止对应脚本（每个脚本独立）

8. 提示与技巧

  • 善用 @error continue：批量操作时加上这一行，避免因为一张卡不存在而导致整个脚本中断。
  • 先检查再运行：写完脚本先点「检查」，能提前发现拼写错误。
  • wait 的作用：如果发现操作没生效，试试在动作之间加 wait 1 到 wait 3（秒），给游戏一些处理时间。需要精确帧控制时用 wait_frame。
  • 选择器省着用：如果场上只有一张目标卡牌，不需要写选择器，直接写卡牌名就行。
  • @silent 避免打扰：频繁执行的脚本加上 @silent，执行完不弹对话框。
  • @hotkey 一键触发：常用脚本绑定一个快捷键，随时按一下就能执行。

WikiMod Script System Guide

1. Quick Start

Open the Anything Tool and find the "Script Tool" page. You'll see the script list on the left and the editor on the right.

Try writing your first script:

River.Drink

Click "Run" — the script will automatically perform the "Drink" action on "River". That's it.

2. Basics

What is a Script

A script is a piece of text that tells the game "automatically do these things for me". You can use it to:

  • Repeat an action (e.g. chopping wood over and over)
  • Run multiple steps in order (e.g. add water → add material → cook)
  • Decide what to do based on conditions (e.g. "if there's jerky, eat it; otherwise skip")

Script Files

Scripts are saved in BepInEx/config/WikiMod/Scripts/ with the .wks extension. You can also edit them directly with any text editor.

The script name is the file name (without extension), shown in the list on the left.

UI Buttons

  • New — Create a blank script
  • Save — Save the current edits to file
  • Check — Check the script for syntax errors
  • Run — Execute the script
  • Stop — Abort the running script
  • Open Folder — Open the scripts directory in the file explorer

You can also click the "Hotkey: None" button to bind a per-script hotkey.

Hotkeys

Each script can be bound to a hotkey via the @hotkey directive or the UI button. Press the key to run the script; press it again to stop.

3. Script Syntax

3.1 Comments and Directives

# This is a comment, not executed.
# Use it for notes.

@error stop
@hotkey F5
@silent

Comments: Lines starting with # are ignored — write whatever you like.

@error: Decides what to do when an error occurs:

  • @error stop — Stop on error (default)
  • @error continue — Skip the failing step and keep going

@hotkey: Binds a hotkey to the script. The value is a Unity KeyCode name (e.g. F5, Tab, Alpha1). Once bound, pressing the key runs the script.

@silent: Add this and no result dialog will pop up after execution. Suitable for short, frequently-run scripts.

3.2 Card Operations

This is the heart of scripting — automating card actions.

Single Card Action (run an action on a card)

River.Drink
Campfire.Cook

Format: CardName.ActionName

Means "find this card, then perform this action" — exactly like right-clicking a card in-game and choosing one of its options.

Card Interaction (drag one card onto another)

Axe_Stone+TreeOakLarge
Firewood+Campfire

Format: GivenCard+ReceivingCard

Means "drop the left card onto the right card" — the same as drag-and-drop in-game.

Standalone Action (without a card)

Rest
North
do Rest

Format: just the action name, or do ActionName

When you write a bare action name, the system searches in this order:

  1. Time options (e.g. "Rest", "Sleep")
  2. Actions on cards in the current scene (e.g. directional movement on the location card like "North", "South")

This is syntactic sugar — when the action name is unique in the current environment, you don't need to specify a card.

Wait

wait 2

Pauses the script for the given number of seconds (decimals supported). Useful when an operation needs an animation to finish or resources to refresh.

wait_frame 5

Wait by frames — pause for the given number of frames. Use when you need precise frame control.

wait_until exists(River) timeout 10

Waits for a condition to become true before continuing. The optional timeout specifies the timeout in seconds (default 60s); after timeout, execution continues anyway.

3.3 Card Selectors

When the scene has multiple cards with the same name, selectors let you pick which one to operate on.

Default (first match)

River.Drink

Without any selector, the first matching card is used.

By Index

River[0].Drink     # 1st card
River[1].Drink     # 2nd card
River[2].Drink     # 3rd card

Indexes start at 0. [0] is the first match, [1] is the second, and so on.

By Property

Jerky[max:Spoilage].Eat     # Eat the most spoiled one first
Jerky[min:Spoilage].Eat     # Eat the least spoiled one first
  • [max:property] — pick the card with the highest value of that property
  • [min:property] — pick the card with the lowest value of that property

The property name can be the in-game display name (e.g. "Spoilage", "Fuel", "Durability") or the internal English name.

Condition Filters

Jerky[Spoilage>80].Eat                  # Only pick jerky with spoilage > 80
Chest[inventory>0].Empty                # Only pick chests with items inside
Jerky[Spoilage>50, max:Spoilage].Eat   # Filter then pick the most spoiled
Wood[Durability>=10, 0]                 # Filter then take the first

Write property operator value inside brackets to filter candidates. Only cards meeting the condition are considered.

  • Supported operators: >, <, >=, <=, =
  • Multiple filters and one selection strategy (max:/min:/index) can be combined with commas
  • Special property inventory: the total item count inside the card (excludes empty slots)

Location Filter

Jerky[in:SafetyJar].Eat                     # Only pick jerky inside the safety jar
Jerky[in:SafetyJar, max:Spoilage].Eat       # Most spoiled jerky in the safety jar
Firewood[in:location]                        # Only pick firewood on the outdoor board
Axe[in:hand]                                 # Only pick axes in hand
Armor[in:equipped]                           # Only pick equipped armor
Plank[in:base]                               # Only pick planks inside base/indoor

[in:location] restricts the search to cards at a specific location. Can be combined with condition filters and selection strategies.

Special location keywords:

Keyword Meaning
hand / 手中 Cards in the player's hand
equipped / 装备 Cards currently equipped
location / 场景 Cards in the current scene (outdoor)
base / 场上 Cards on the base board (indoor)

Other values match by container name (e.g. in:SafetyJar, in:Backpack).

Content Filter

SafetyJar[has:Jerky]                     # Safety jars containing jerky
Kettle[has:Water]                        # Kettles containing water (checks items and liquids)
Container[has:Jerky, inventory>3]        # Containers with jerky and more than 3 items

[has:name] filters cards that contain the specified item or liquid. It checks both internal items (CardsInInventory) and contained liquid (ContainedLiquid). Can be combined with other filters.

Quoted Names for Special Characters

If a card or action name contains +, [, ], or whitespace, wrap it in double quotes:

"Card With Spaces"[0].Action

3.4 Blueprint Spawn and Inspect

Spawn Blueprint: blueprint

blueprint WoodShavings
blueprint WoodShavings 3

Format: blueprint BlueprintCardName [count]

Spawns one or more blueprint card instances in the current environment. Count is optional and defaults to 1. Spawn only — no fill, no build.

⚠ blueprint only accepts blueprint cards. Passing a regular item raises blueprint 仅支持蓝图卡，<X> 不是蓝图卡 — to prevent scripts from being used to conjure arbitrary items as a cheat.

The legacy spawn command is disabled and raises spawn 命令已禁用. For regular items, build them through their blueprint instead.

One-Shot Build: build ⭐

build WoodShavings
build Bp_Cabin

For batch building, wrap build in a repeat block:

repeat 5 {
    build WoodenPlankHouse
}

Format: build BlueprintCardName

The recommended way to build anything from a blueprint — a single line that runs the whole pipeline: spawn the blueprint (if no unfinished one exists in this env) → open the construction panel → wait 2 frames → AutoFill → click Build. One build per call.

Behavior:

  • Reuses, doesn't duplicate: if an unfinished blueprint of the same kind already exists in the current environment, build fills and finishes that one instead of spawning a duplicate.
  • Fails fast: any step's failure (not unlocked / missing material / missing durability / stat too low / blocking status / etc.) stops the whole script and logs the specific reason (e.g. 自动填充后仍无法制作: 缺卡牌: 石头; 属性不满足: 体力).
  • Searches only unlocked blueprints: build resolves the name strictly against your unlocked blueprint list, so build Campfire lands on Bp_Campfire even when a regular "Campfire" card is also in the environment. If the blueprint isn't unlocked, it errors with 未找到已解锁的蓝图: <name>.
  • Tags rejected: passing a CardTag (e.g. build Food) is rejected at validation time.
  • Prefer the internal ID: build Bp_Cabin is the safest form — it sidesteps localization changes and rare cases where two blueprints share a display name.

Open Panel: inspect

inspect River
inspect Plank[0]

Format: inspect CardSelector

Opens the inspection panel for the given card. Typically used together with click.

Click Buttons: click

inspect River
click Drink

Format: click ButtonName

Clicks a button on the currently open panel. You must inspect a card first before you can click. The button name is the text shown on the panel.

Supported button types: option buttons, grouped option buttons, empty-inventory buttons, build/deconstruct buttons, auto-fill buttons, and more.

3.5 Message Commands

Floating Toast: toast

toast Hello, world
toast "Harvest done — got 5 planks"

Format: toast Message

Shows a floating message on screen that auto-dismisses. Does not block script execution.

Modal Alert: alert

alert Please confirm to continue
alert "Operation complete"

Format: alert Message

Shows a centered dialog. The script only continues after the user clicks "Close" or presses ESC. Use it when you need to pause and wait for user confirmation.

Consolidate Liquids: liquid_merge

liquid_merge Waterskin
liquid_merge Waterskin[in:hand]
liquid_merge Container[has:Water]

Format: liquid_merge Selector

Consolidates liquids across matching containers so that fewer containers hold all the liquid (fills up the fullest first). Different liquid types are grouped separately — never mixed.

Uses the native liquid transfer mechanism, so game rules like minimum retention per container are respected. Does nothing if fewer than 2 containers with liquid match.

Template Expressions

Both toast and alert support {expression} placeholders that are replaced with live game data at runtime:

toast Stone axe durability: {Axe_Stone.Durability}
toast Jerky count: {count(Jerky)}
alert "Current hunger: {Hunger}"

Supported expressions:

  • {Card.Property} — card property value (e.g. {Axe_Stone.Durability})
  • {Card[selector].Property} — property with selector (e.g. {Axe_Stone[0].Durability})
  • {count(CardName)} — card count (e.g. {count(Jerky)})
  • {exists(CardName)} — whether the card exists (renders as "Yes" / "No")
  • {inventory_count(CardName)} — total item count inside the card's inventory (e.g. {inventory_count(Backpack)})
  • {StatName} — game stat value (e.g. {Hunger}, {HP})

If an expression fails to evaluate, the original {expression} text is kept verbatim — it won't break the message.

3.6 Control Flow

Loop: repeat

repeat 10 {
    River.Drink
}

Repeats the contents of the braces N times. The example above drinks from the river 10 times in a row.

You can nest loops:

repeat 3 {
    Axe_Stone+TreeOakLarge
    repeat 2 {
        River.Drink
    }
}

Conditional: if / else if / else

if exists(River) {
    River.Drink
}

Only runs the body when the condition is true.

You can chain else if and else:

if exists(River) {
    River.Drink
} else if exists(Waterskin) {
    Waterskin.Drink
} else {
    toast No water source
}

Note: { must be on the same line as if / else if / else. else must go on the line right after the previous }.

Conditional Loop: while

while Campfire.Fuel < 30 and exists(Firewood) {
    Firewood+Campfire
}

Repeats as long as the condition is true. Each iteration yields a frame to avoid blocking. To prevent infinite loops, the maximum is 10000 iterations.

Loop Control: break / continue / stop

repeat 10 {
    if not exists(Jerky) {
        break
    }
    Jerky.Eat
}
  • break — exit the current loop
  • continue — skip the rest of this iteration and start the next
  • stop (or exit) — terminate the entire script immediately

break and continue can only be used inside loops (repeat / while / foreach).

Variables: var

var target = Jerky[max:Spoilage]
$target.Eat

var count = 5
var backup = $target

Define a variable with var:

  • Number: var x = 42
  • Card reference: var t = Jerky[max:Spoilage] (the card is resolved at definition time)
  • Property value: var v = Jerky[max:Spoilage].Spoilage (numeric value of a card property)
  • Copy a variable: var b = $t (copies another variable's value)

Reference card variables in card operations and conditions with $varName:

var t = Jerky[max:Spoilage]
$t.Eat
if $t.Spoilage > 80 {
    toast About to spoil!
}

In template expressions, use {$varName}:

var t = Jerky[max:Spoilage]
toast Spoilage: {$t.Spoilage}
log Current target: {$t}

Iteration: foreach

foreach item in Jerky {
    if $item.Spoilage > 80 {
        $item.Eat
    }
}

Iterates over all matching cards with the same name in the scene. Each iteration binds the variable to the current card. Reference it with $varName in conditions and card operations. break and continue are supported.

Sub-scripts: call

call SubScriptName

Calls another script by name. Sub-scripts have an independent variable scope (they don't share variables with the parent). Sub-script logs are merged into the parent. If a sub-script errors out, the error propagates to the parent.

Logging: log

log Current fuel: {Campfire.Fuel}
log Variable value: {$target.Spoilage}

Writes to the log without showing a popup. Supports template expressions. Logs can be reviewed in the execution result.

3.7 Conditional Expressions

exists — does the card exist

if exists(River) {
    River.Drink
}

Checks whether the card exists in the current scene.

count — number of cards

if count(Jerky) >= 3 {
    Jerky.Eat
}

Checks how many of a card exist in the current scene. Comparable with >, <, >=, <=, ==, !=.

Property Comparison

if Campfire.Fuel > 10 {
    # Plenty of fuel, no need to add wood
}

if Jerky.Spoilage > 80 {
    # Going bad, eat it now
    Jerky[min:Spoilage].Eat
}

Checks a card's property value. Format: CardName.Property operator number

Stat Comparison

if HP > 50 {
    # Health is sufficient
}

Checks a global game stat value. Format: StatName operator number

Variable Comparison

var c = Leaves[min:Moisture].Moisture
if $c > 100 {
    toast Moisture is high: {$c}
}

Checks a variable value. Format: $varName operator number. The variable must be a numeric value (obtained via var x = Card.Property).

You can also access a card variable's properties directly inside conditions:

var t = Jerky[max:Spoilage]
if $t.Spoilage > 80 {
    $t.Eat
}

Logical Operators

Conditions can be combined with logical operators:

if exists(River) and count(Jerky) >= 3 {
    River.Drink
}

if not exists(Campfire) or Campfire.Fuel < 5 {
    # No campfire or not enough fuel
}

if (exists(River) and exists(Axe_Stone)) or count(Jerky) > 10 {
    Axe_Stone+TreeOakLarge
}
  • and or && — logical AND, both sides must be true
  • or or || — logical OR, either side being true is enough
  • not or ! — logical NOT, negates the value
  • Use () for grouping / precedence

3.8 Full Command Forms

The shorthand forms (Card.Action and Card+Card) are actually syntactic sugar. Their full forms:

# Full form for a single card action
do River.Drink
do Jerky[min:Spoilage].Eat

# Full form for card interaction
interact Axe_Stone TreeOakLarge
interact Stone Axe Oak Tree

Both styles do exactly the same thing — pick whichever you prefer.

4. Naming Rules

Writing Card Names

The script tries to match card names in this order:

  1. The display name in the current language
  2. The English name
  3. The internal resource ID (e.g. Bp_WoodShavings)

Recommendation: just use the in-game display name in your current language — e.g. "River", "Stone Axe", "Oak Tree".

Card Tags Are Supported

Besides direct card names, you can also use card tag names. The system first matches by card name; if no card matches, it falls back to tag matching.

Axe+Tree

Here both "Axe" and "Tree" are tag names (CardTag). The system finds cards with the corresponding tags in the current environment and performs the interaction.

Tag names support these forms:

  1. The tag's display name in the current language (e.g. "Axe", "Tree")
  2. The tag's English name
  3. The tag's internal resource ID (e.g. tag_HumanFood)

Tags can be used anywhere a card name is expected:

  • Card actions: Tag.Action
  • Card interactions: Axe+Tree
  • Conditions: exists(Tag), count(Tag)
  • Selectors: Tag[max:property], Tag[min:property]

Writing Action Names

Same idea — use the display name shown in-game. For example, if you right-click "River" and see "Drink", write River.Drink.

Writing Property Names

Properties can use the in-game display name (e.g. "Durability", "Fuel") or the internal English name. Which property means what depends on the card.

Environment Limitations

Scripts can only operate on cards in the current environment. If you're outdoors, you can't operate on cards inside a house; if you're in a tent, you can't operate on cards outside.

5. Error Handling

The Check Button

Click "Check" before running to catch problems early:

  • Syntax errors: typos, missing brackets, etc.
  • Semantic errors: card name doesn't exist, action name is wrong

Errors appear below the editor with line numbers and reasons.

Two Error Modes

@error stop       # Stop the entire script on any error (default)
@error continue   # Skip the failing step and keep going

When should you use continue?

When you're processing in bulk and some cards may already be gone:

@error continue

repeat 20 {
    Jerky.Eat
}

Even if there are only 3 jerkies, the script keeps going after eating them all (instead of stopping with an error).

Common Errors

  • Card not found: xxx — wrong card name; check the actual in-game name
  • Action not found: xxx — wrong action name; right-click the card to see the real names
  • Expected '{' — the loop or if is missing its brace; write repeat 5 { or if ... {
  • Missing '}' — an unclosed brace; add } at the end of the block

6. Practical Examples

Example 1: Repeated Water Collection

@error continue

repeat 10 {
    River.Drink
}

Drinks from the river 10 times in a row. @error continue ensures the script doesn't stop midway even if the river is gone.

Example 2: Conditional Auto-Refuel

@error continue

repeat 20 {
    if exists(Campfire) {
        if exists(Firewood) {
            Firewood+Campfire
        }
    }
}

Checks that both the campfire and firewood exist; if both, automatically adds wood. Repeats 20 times.

Example 3: Smart Selector

@error stop

if exists(Jerky) {
    Jerky[max:Spoilage].Eat
}

Eats the most spoiled jerky first to avoid waste.

Example 4: Chopping Trees

@error continue

repeat 5 {
    Axe_Stone+TreeOakLarge
}

Uses the stone axe on the oak tree 5 times — bulk chopping.

Example 5: One-Shot Build

@silent

build WoodShavings

build runs the whole pipeline in one line: (if no unfinished one is in the env) spawn the blueprint → open the panel → AutoFill → click Build. @silent suppresses the result popup. Unlocked blueprints only; if materials/conditions don't satisfy, the log shows the exact reason.

For batch building, wrap build in a repeat block:

repeat 5 {
    build WoodShavings
}

Example 6: Toast and Confirmation

@error continue

repeat 5 {
    Axe_Stone+TreeOakLarge
}
toast Chopping done. Axe durability: {Axe_Stone.Durability}
alert "Continue?"

After chopping trees, toast shows the axe's durability, then alert waits for confirmation.

Example 7: Combined Logical Condition

@error continue
@hotkey F5

repeat 10 {
    if exists(Firewood) and Campfire.Fuel < 30 {
        Firewood+Campfire
    }
}

Only adds firewood when wood is available AND the campfire's fuel is below 30. Bound to F5 for one-press execution.

7. Quick Reference

Syntax at a Glance

  • Card.Action — single card action (e.g. River.Drink)
  • CardA+CardB — card interaction (e.g. Axe_Stone+TreeOakLarge)
  • ActionName — standalone action with no card (e.g. Rest, North)
  • wait N — wait N seconds (e.g. wait 2, wait 0.5)
  • wait_frame N — wait N frames (e.g. wait_frame 5)
  • wait_until cond [timeout N] — wait for a condition (e.g. wait_until exists(River) timeout 10)
  • repeat N { } — repeat N times
  • while cond { } — conditional loop
  • foreach var in CardName { } — iterate over cards
  • if cond { } — conditional execution
  • if ... { } else if ... { } else { } — multi-branch conditional
  • var name = value — define a variable
  • break — exit a loop
  • continue — skip this iteration
  • stop / exit — terminate the script
  • call ScriptName — call a sub-script
  • log Message — write to the log
  • blueprint BlueprintName [count] — spawn a blueprint card (blueprint cards only, e.g. blueprint WoodShavings)
  • build BlueprintName — one-shot blueprint build (spawn→inspect→AutoFill→Build, all in one; e.g. build Bp_Cabin)
  • inspect Selector — open inspection panel (e.g. inspect River)
  • click ButtonName — click a panel button (e.g. click Drink)
  • toast Message — show a floating toast (e.g. toast Done)
  • alert Message — show a modal alert (e.g. alert Please confirm)
  • liquid_merge Selector — consolidate liquids (e.g. liquid_merge Waterskin[in:hand])
  • @error stop/continue — error policy
  • @hotkey KeyName — bind a hotkey (e.g. @hotkey F5)
  • @silent — silent execution
  • # text — comment

Selectors

  • CardName — first match
  • CardName[0] — 1st card
  • CardName[1] — 2nd card
  • CardName[max:property] — highest property value
  • CardName[min:property] — lowest property value
  • CardName[property>N] — first card meeting the condition (supports > < >= <= =)
  • CardName[inventory>N] — first card with more than N inventory items
  • CardName[in:location] — only cards at specified location (hand/equipped/location/base/container name)
  • CardName[filter, max:property] — filter then sort (comma-separated)
  • "Special Name" — name containing special characters

Conditions

  • exists(CardName) — whether the card is in the scene (tag names also supported)
  • count(CardName) > N — whether the count is greater than N (tag names also supported)
  • Card.Property > N — whether a property is greater than N
  • $var.Property > N — whether a variable card's property is greater than N
  • StatName > N — whether a game stat is greater than N
  • $var > N — whether a numeric variable is greater than N
  • cond1 and cond2 — logical AND
  • cond1 or cond2 — logical OR
  • not cond — logical NOT
  • (cond) — grouping with parentheses

Template Expressions (for toast / alert / log)

  • {Card.Property} — property value (e.g. {Axe_Stone.Durability})
  • {Card[selector].Property} — with selector (e.g. {Axe_Stone[0].Durability})
  • {count(CardName)} — count (e.g. {count(Plank)})
  • {exists(CardName)} — existence (renders "Yes" / "No")
  • {inventory_count(CardName)} — inventory item count (e.g. {inventory_count(Backpack)})
  • {StatName} — stat value (e.g. {Hunger})
  • {$varName} — variable value (e.g. {$target})
  • {$varName.Property} — variable card's property (e.g. {$target.Spoilage})

Comparison Operators

>, <, >=, <=, == (equal), != (not equal)

Hotkeys

  • @hotkey binding — run / stop the bound script (per-script independent)

8. Tips and Tricks

  • Use @error continue for batches: add this line for bulk operations to avoid the entire script stopping just because one card is missing.
  • Check before running: click "Check" after writing — it catches typos before runtime.
  • What wait is for: if an operation doesn't seem to take effect, try inserting wait 1 to wait 3 (seconds) between actions to give the game time to process. Use wait_frame when you need precise frame control.
  • Skip selectors when possible: if there's only one matching card in the scene, you don't need a selector — just write the card name.
  • @silent to stay quiet: add @silent to scripts you run frequently so no dialog pops up after each run.
  • @hotkey for one-press execution: bind a hotkey to your favorite scripts so you can trigger them instantly.
